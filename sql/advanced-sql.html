01 • CONDITIONAL LOGIC

CASE WHEN

CASE adds conditional logic directly inside SQL expressions.

Syntax / pattern

CASE WHEN condition THEN result ELSE result END

Example

SELECT name, salary,
 CASE WHEN salary >= 100000 THEN 'High' ELSE 'Standard' END AS band
FROM employees;

🎯 Interview question: Can CASE be used with aggregates?

Answer: Yes, conditional aggregation often uses SUM(CASE WHEN condition THEN value ELSE 0 END).

🎯 Interview question: Common use case?

Answer: Pivot-like counts, segmentation and conditional metrics.

02 • COMBINING RESULT SETS

UNION vs UNION ALL

UNION combines compatible result sets and removes duplicates; UNION ALL keeps duplicates.

Syntax / pattern

SELECT ... UNION ALL SELECT ...

Example

SELECT city FROM customers_india
UNION ALL
SELECT city FROM customers_usa;

🎯 Interview question: Which is usually faster?

Answer: UNION ALL, because it does not need duplicate elimination.

🎯 Interview question: What must match?

Answer: The SELECT statements need compatible column counts and compatible data types.

03 • SAVED QUERY INTERFACE

Views

A view is a named query that can simplify repeated access patterns.

Syntax / pattern

CREATE VIEW view_name AS SELECT ...;

Example

CREATE VIEW active_employees AS
SELECT id, name, department
FROM employees
WHERE active = true;

🎯 Interview question: View vs table?

Answer: A regular view stores query definition, not necessarily separate data; a table stores data.

🎯 Interview question: What is a materialized view?

Answer: A persisted query result that may need refresh, depending on the database.

04 • ACCESS PATHS

Indexes

An index is a data structure that can speed up lookups, joins and sorting patterns, at the cost of storage and write overhead.

Syntax / pattern

CREATE INDEX idx_name ON table(column);

Example

CREATE INDEX idx_orders_customer ON orders(customer_id);

🎯 Interview question: Why not index every column?

Answer: Indexes slow inserts/updates/deletes and consume storage.

🎯 Interview question: What is a composite index?

Answer: An index on multiple columns; column order matters for which predicates can efficiently use it.

05 • CONSISTENCY

Transactions & ACID

A transaction groups statements into an all-or-nothing unit of work.

Syntax / pattern

BEGIN;
UPDATE ...;
COMMIT; -- or ROLLBACK;

Example

BEGIN;
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;

🎯 Interview question: What does ACID stand for?

Answer: Atomicity, Consistency, Isolation and Durability.

🎯 Interview question: COMMIT vs ROLLBACK?

Answer: COMMIT makes the transaction permanent; ROLLBACK discards uncommitted changes.

06 • PERFORMANCE THINKING

Query Optimization

Good SQL performance starts with reading fewer rows, using selective filters, sensible joins and appropriate indexes.

Syntax / pattern

EXPLAIN SELECT ...

Example

EXPLAIN SELECT *
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.order_date >= '2026-01-01';

🎯 Interview question: First things to check in a slow query?

Answer: Execution plan, row counts, filters, join conditions, indexes, unnecessary SELECT * and data skew/cardinality.

🎯 Interview question: Why is SELECT * discouraged?

Answer: It can transfer and process unnecessary columns and makes schema dependencies less explicit.
