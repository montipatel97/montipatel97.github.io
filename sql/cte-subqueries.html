01 • NAMED QUERY STEP

Common Table Expression

A CTE is a named temporary result used by the statement that follows it.

Syntax / pattern

WITH name AS (
  SELECT ...
)
SELECT ... FROM name;

Example

WITH dept_avg AS (
 SELECT department, AVG(salary) AS avg_salary
 FROM employees GROUP BY department
)
SELECT * FROM dept_avg;

🎯 Interview question: CTE vs subquery?

Answer: Both can structure logic; CTEs are often easier to read and reuse within one statement.

🎯 Interview question: Is a CTE always faster?

Answer: No. Performance depends on the database optimizer and query; readability is usually the main reason to use one.

02 • HIERARCHIES

Recursive CTE

A recursive CTE repeatedly combines an anchor query with rows produced from earlier iterations.

Syntax / pattern

WITH RECURSIVE cte AS (
 anchor_query
 UNION ALL
 recursive_query
) SELECT * FROM cte;

Example

WITH RECURSIVE org AS (
 SELECT id, name, manager_id, 1 AS lvl FROM employees WHERE manager_id IS NULL
 UNION ALL
 SELECT e.id, e.name, e.manager_id, o.lvl + 1
 FROM employees e JOIN org o ON e.manager_id = o.id
) SELECT * FROM org;

🎯 Interview question: Typical use?

Answer: Hierarchies such as org charts, category trees and parent-child structures.

🎯 Interview question: Why is UNION ALL commonly used?

Answer: It avoids duplicate elimination overhead and is generally appropriate for recursive traversal.

03 • SINGLE VALUE

Scalar subquery

A scalar subquery returns one value and can be used in SELECT, WHERE or expressions.

Syntax / pattern

SELECT ... WHERE value > (SELECT AVG(value) FROM table);

Example

SELECT name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);

🎯 Interview question: What happens if a scalar subquery returns multiple rows?

Answer: Most databases raise an error because a single value was expected.

🎯 Interview question: When is it useful?

Answer: Comparing each row against a global aggregate or single lookup value.

04 • ROW-BY-ROW DEPENDENCY

Correlated subquery

A correlated subquery references the outer query, so its result depends on the current outer row.

Syntax / pattern

SELECT ... FROM a x
WHERE value > (SELECT AVG(value) FROM a y WHERE y.group = x.group);

Example

SELECT e.name, e.salary
FROM employees e
WHERE e.salary > (
 SELECT AVG(e2.salary)
 FROM employees e2
 WHERE e2.department = e.department
);

🎯 Interview question: Why can correlated subqueries be expensive?

Answer: The logical dependency can require repeated evaluation, although optimizers may rewrite the plan.

🎯 Interview question: Alternative?

Answer: A GROUP BY/CTE or window function may express the same problem more efficiently.

05 • CHECK FOR MATCHES

EXISTS & NOT EXISTS

EXISTS tests whether a subquery returns at least one row.

Syntax / pattern

WHERE EXISTS (SELECT 1 FROM ... WHERE ...)

Example

SELECT c.customer_name
FROM customers c
WHERE EXISTS (
 SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
);

🎯 Interview question: EXISTS vs IN?

Answer: Both can express membership; EXISTS is often natural for correlated existence checks. NULL behavior can make IN/NOT IN tricky.

🎯 Interview question: Why is NOT EXISTS safer than NOT IN with NULLs?

Answer: NOT IN can behave unexpectedly if the subquery contains NULL; NOT EXISTS avoids that particular three-valued logic issue.
