01 • WINDOW FOUNDATION

OVER(), PARTITION BY & ORDER BY

A window function calculates over a set of rows while still returning individual rows.

Syntax / pattern

function() OVER (PARTITION BY group_col ORDER BY sort_col)

Example

SELECT employee, department, salary,
       AVG(salary) OVER (PARTITION BY department) AS dept_avg
FROM employees;

🎯 Interview question: GROUP BY vs window function?

Answer: GROUP BY collapses rows into groups. A window function keeps the original row count.

🎯 Interview question: What does PARTITION BY do?

Answer: It creates independent windows, similar to groups, for the calculation.

02 • ASSIGN POSITIONS

ROW_NUMBER, RANK & DENSE_RANK

Use ranking functions to assign positions inside an ordered window.

Syntax / pattern

ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC)

Example

SELECT name, salary,
 ROW_NUMBER() OVER (ORDER BY salary DESC) rn,
 RANK() OVER (ORDER BY salary DESC) rnk,
 DENSE_RANK() OVER (ORDER BY salary DESC) drnk
FROM employees;

🎯 Interview question: RANK vs DENSE_RANK?

Answer: RANK leaves gaps after ties; DENSE_RANK does not.

🎯 Interview question: How do you get top 3 salaries per department?

Answer: Use DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) and filter rank <= 3 in an outer query/CTE.

03 • LOOK AROUND

LAG & LEAD

LAG reads a previous row and LEAD reads a following row according to the window ordering.

Syntax / pattern

LAG(value, offset) OVER (PARTITION BY ... ORDER BY ... )

Example

SELECT order_date, sales,
       LAG(sales) OVER (ORDER BY order_date) AS previous_sales
FROM daily_sales;

🎯 Interview question: How do you calculate day-over-day change?

Answer: Subtract LAG(sales) from sales using the same date ordering.

🎯 Interview question: Why is ORDER BY essential here?

Answer: Previous and next only have meaning when row order is defined.

04 • CUMULATIVE METRICS

Running total

A running total sums from the start of the partition through the current row.

Syntax / pattern

SUM(value) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)

Example

SELECT order_date, sales,
 SUM(sales) OVER (ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_sales
FROM daily_sales;

🎯 Interview question: Why specify ROWS explicitly?

Answer: It clearly defines a row-based frame and avoids ambiguity with peer rows sharing the same ORDER BY value.

🎯 Interview question: Running total per customer?

Answer: Add PARTITION BY customer_id before ORDER BY date.

05 • ROLLING WINDOWS

Moving average

A moving average uses a sliding frame around the current row, commonly the current row plus previous N rows.

Syntax / pattern

AVG(value) OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)

Example

SELECT order_date, sales,
 AVG(sales) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS moving_avg_7
FROM daily_sales;

🎯 Interview question: What does 6 PRECEDING + CURRENT ROW mean?

Answer: A 7-row rolling window: six earlier rows plus the current row.

🎯 Interview question: ROWS vs RANGE?

Answer: ROWS counts physical rows; RANGE is value-based and can include peers with equal ORDER BY values.
