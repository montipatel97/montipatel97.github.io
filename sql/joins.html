01 • MATCHING ROWS

INNER JOIN

Returns only rows with a matching join condition in both tables.

Syntax / pattern

SELECT ... FROM a INNER JOIN b ON a.id = b.id;

Example

SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.id;

🎯 Interview question: INNER JOIN vs LEFT JOIN?

Answer: INNER JOIN keeps only matches. LEFT JOIN keeps every row from the left table and fills unmatched right-side columns with NULL.

🎯 Interview question: How do you find unmatched rows?

Answer: Use a LEFT JOIN and filter where the right table's primary key is NULL.

02 • PRESERVING LEFT TABLE

LEFT JOIN

Keeps every row from the left table. Matching right-side data is added when available.

Syntax / pattern

SELECT ... FROM a LEFT JOIN b ON a.id = b.id;

Example

SELECT c.customer_name, o.order_id
FROM customers c
LEFT JOIN orders o ON c.customer_id = o.customer_id;

🎯 Interview question: WHERE vs ON in a LEFT JOIN?

Answer: A right-table condition in WHERE can remove NULL rows and effectively turn the result into an INNER JOIN. Put optional match conditions in ON when you want to preserve left rows.

🎯 Interview question: How do you find customers with no orders?

Answer: LEFT JOIN orders and use WHERE o.order_id IS NULL.

03 • OTHER OUTER JOINS

RIGHT JOIN & FULL OUTER JOIN

RIGHT JOIN preserves every row from the right table. FULL OUTER JOIN preserves rows from both tables, matching where possible.

Syntax / pattern

SELECT ... FROM a FULL OUTER JOIN b ON a.id = b.id;

Example

SELECT a.id, b.id
FROM table_a a
FULL OUTER JOIN table_b b ON a.id = b.id;

🎯 Interview question: When is RIGHT JOIN useful?

Answer: It is logically equivalent to swapping table order and using LEFT JOIN; many teams prefer LEFT JOIN for readability.

🎯 Interview question: What does FULL OUTER JOIN help find?

Answer: Records present only in A, only in B, and matching records—useful for reconciliation.

04 • CARTESIAN PRODUCT

CROSS JOIN

Combines every row from one table with every row from another table. If A has m rows and B has n rows, the result has m × n rows.

Syntax / pattern

SELECT ... FROM a CROSS JOIN b;

Example

SELECT c.color, s.size
FROM colors c
CROSS JOIN sizes s;

🎯 Interview question: Why can CROSS JOIN be dangerous?

Answer: Large inputs can explode into a huge result set.

🎯 Interview question: A real use case?

Answer: Generating all date × product or color × size combinations.

05 • JOINING A TABLE TO ITSELF

SELF JOIN

A table can be joined to itself using aliases, commonly for employee-manager hierarchies.

Syntax / pattern

SELECT ... FROM employees e JOIN employees m ON e.manager_id = m.id;

Example

SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.id;

🎯 Interview question: Why are aliases required?

Answer: They distinguish the two logical roles of the same table.

🎯 Interview question: Common self-join use case?

Answer: Employee-manager relationships or comparing rows within the same entity.
