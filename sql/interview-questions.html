🟡 Medium💻 Query Writing

Find the second-highest distinct salary from an employees table.

Think about ties: should two employees with the same salary create multiple ranks?

Show answer +
WITH ranked AS (
 SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
 FROM employees
)
SELECT DISTINCT salary
FROM ranked
WHERE rnk = 2;

Why: DENSE_RANK handles duplicate salaries correctly when the question asks for the second-highest distinct value.

01

CORE SQL

Fundamentals & concepts

What is the difference between WHERE and HAVING?

Show answer +

Interview answer: WHERE filters individual rows before aggregation. HAVING filters groups after GROUP BY and aggregation. Use WHERE whenever possible before grouping because it reduces the rows that need to be aggregated.

SELECT department, COUNT(*) AS cnt
FROM employees
WHERE active = true
GROUP BY department
HAVING COUNT(*) > 10;

What is the logical execution order of a SQL query?

Show answer +

Answer: A common logical order is FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT/OFFSET. This explains why a SELECT alias usually cannot be referenced in WHERE.

COUNT(*) vs COUNT(column) vs COUNT(DISTINCT column)?

Show answer +

Answer: COUNT(*) counts rows. COUNT(column) counts non-NULL values. COUNT(DISTINCT column) counts unique non-NULL values.

02

TABLE RELATIONSHIPS

Joins

How do you find customers who never placed an order?

Show answer +
SELECT c.customer_id, c.customer_name
FROM customers c
LEFT JOIN orders o
  ON c.customer_id = o.customer_id
WHERE o.customer_id IS NULL;

Why it works: LEFT JOIN preserves every customer; NULL on the order side means no match. NOT EXISTS is another excellent answer.

Why can a LEFT JOIN accidentally behave like an INNER JOIN?

Show answer +

Answer: Filtering a right-table column in WHERE removes rows where the right side is NULL. Put optional right-table matching conditions inside the ON clause when you still need unmatched left rows.

What is an anti join?

Show answer +

Answer: It returns rows from one table that have no matching row in another. In standard SQL, it is commonly written using NOT EXISTS or LEFT JOIN ... WHERE right_key IS NULL.

03

SUMMARIZE DATA

Aggregations

Find the department with the highest average salary.

Show answer +
SELECT department, AVG(salary) AS avg_salary
FROM employees
GROUP BY department
ORDER BY avg_salary DESC
LIMIT 1;

Interview extension: If ties must all be returned, rank the grouped results with DENSE_RANK instead of LIMIT 1.

Can you use aggregate functions in WHERE?

Show answer +

Answer: Not directly at the same query level because WHERE runs before aggregation. Use HAVING or put the aggregation in a subquery/CTE.

Find duplicate records.

Show answer +
SELECT email, COUNT(*) AS occurrences
FROM users
GROUP BY email
HAVING COUNT(*) > 1;
04

HIGHEST-YIELD TOPIC

Window Functions

ROW_NUMBER vs RANK vs DENSE_RANK?

Show answer +

Answer: ROW_NUMBER always assigns unique sequential numbers. RANK gives ties the same rank and leaves gaps. DENSE_RANK gives ties the same rank without gaps. For second-highest distinct salary, DENSE_RANK is usually the safest choice.

Find the second highest distinct salary.

Show answer +
WITH ranked AS (
  SELECT salary,
         DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
  FROM employees
)
SELECT DISTINCT salary
FROM ranked
WHERE rnk = 2;

Why interviewers like it: It tests ranking, ties and the difference between distinct values and distinct rows.

Find the top 3 earners in each department.

Show answer +
WITH ranked AS (
  SELECT employee_name, department, salary,
         DENSE_RANK() OVER (
           PARTITION BY department
           ORDER BY salary DESC
         ) AS rnk
  FROM employees
)
SELECT *
FROM ranked
WHERE rnk <= 3;

Trap: Use ROW_NUMBER when exactly three rows are required; use RANK/DENSE_RANK when ties should be preserved according to the business requirement.

Calculate a running total.

Show answer +
SELECT order_date,
       amount,
       SUM(amount) OVER (
         ORDER BY order_date
         ROWS BETWEEN UNBOUNDED PRECEDING
                  AND CURRENT ROW
       ) AS running_total
FROM orders;

Answer to explain: The frame starts at the first row and ends at the current row, so the sum grows as rows progress.

Calculate a 7-day moving average.

Show answer +
SELECT order_date,
       sales,
       AVG(sales) OVER (
         ORDER BY order_date
         ROWS BETWEEN 6 PRECEDING
                  AND CURRENT ROW
       ) AS moving_avg
FROM daily_sales;

Important: This is a 7-row moving average, not automatically a true calendar 7-day window when dates are missing. The exact implementation can vary by SQL dialect.

Calculate month-over-month growth using LAG.

Show answer +
SELECT month,
       revenue,
       revenue - LAG(revenue) OVER (ORDER BY month) AS growth,
       100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))
       / NULLIF(LAG(revenue) OVER (ORDER BY month), 0) AS growth_pct
FROM monthly_revenue;

Key point: NULLIF prevents division by zero.

Find employees earning above their department average.

Show answer +
WITH x AS (
  SELECT employee_name, department, salary,
         AVG(salary) OVER (
           PARTITION BY department
         ) AS dept_avg
  FROM employees
)
SELECT *
FROM x
WHERE salary > dept_avg;
05

MULTI-STEP REASONING

CTEs & Subqueries

CTE vs subquery?

Show answer +

Answer: Both can represent an intermediate result. A CTE is often easier to read, name and chain into multiple logical steps. Performance is database- and optimizer-dependent; do not claim that a CTE is always faster.

Find employees earning above their department average using a correlated subquery.

Show answer +
SELECT e.employee_name, e.department, e.salary
FROM employees e
WHERE e.salary > (
  SELECT AVG(e2.salary)
  FROM employees e2
  WHERE e2.department = e.department
);

EXISTS vs IN?

Show answer +

Answer: Both can test membership. EXISTS is especially natural for correlated existence checks. Be careful with NOT IN when the subquery can return NULL; NOT EXISTS is often safer and clearer.

MUST-SOLVE PATTERNS

Classic SQL problems

Delete duplicates while keeping one row.

Show answer +
WITH ranked AS (
  SELECT id,
         ROW_NUMBER() OVER (
           PARTITION BY email
           ORDER BY id
         ) AS rn
  FROM users
)
DELETE FROM users
WHERE id IN (
  SELECT id FROM ranked WHERE rn > 1
);

Note: DELETE syntax differs across databases; in an interview, explain the ranking approach first.

Find consecutive login days.

Show answer +
WITH d AS (
  SELECT DISTINCT user_id, login_date
  FROM logins
),
x AS (
  SELECT user_id, login_date,
         login_date - ROW_NUMBER() OVER (
           PARTITION BY user_id
           ORDER BY login_date
         ) * INTERVAL '1 day' AS grp
  FROM d
)
SELECT user_id,
       MIN(login_date) AS streak_start,
       MAX(login_date) AS streak_end,
       COUNT(*) AS days
FROM x
GROUP BY user_id, grp;

Pattern: This is a classic gaps-and-islands technique. Date arithmetic syntax varies by database.

Find the latest record for each customer.

Show answer +
WITH ranked AS (
  SELECT *,
         ROW_NUMBER() OVER (
           PARTITION BY customer_id
           ORDER BY updated_at DESC
         ) AS rn
  FROM customer_status
)
SELECT *
FROM ranked
WHERE rn = 1;

Find duplicate rows and keep the latest one.

Show answer +

Approach: Use ROW_NUMBER() PARTITION BY the business key and ORDER BY updated_at DESC. Keep rn = 1; rows with rn > 1 are duplicates to remove or archive.
