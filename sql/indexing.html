What is an index?

An index is an auxiliary access structure that can reduce work for suitable predicates, joins and ordering.

Interview focus

Always mention the trade-off: faster reads, more storage and write maintenance.

B-tree indexes

Balanced ordered trees support equality, range predicates and ordered access.

Interview focus

B-tree is the default general-purpose index in many relational databases.

Hash indexes

Hash lookup is primarily suited to equality access where supported.

Interview focus

Know that hash is not a general replacement for ordered or range access.

Clustered vs non-clustered

Terminology and implementation vary by engine; conceptually one organization may align data with an index while secondary indexes are separate.

Interview focus

Avoid presenting one vendor's implementation as universal SQL truth.

Composite indexes

Multiple columns are indexed together; order matters and commonly follows a leftmost-prefix rule.

Interview focus

Choose column order from actual WHERE, JOIN and ORDER BY patterns.

Covering indexes

An index may satisfy a query without visiting base-table data when it contains required columns.

Interview focus

Explain faster reads versus wider indexes and write cost.

Index anti-patterns

Low selectivity, functions, implicit casts and leading wildcards can reduce index usefulness.

Interview focus

Define sargability and rewrite a non-sargable predicate.

Quick interview recap

  1. What is an index?: Always mention the trade-off: faster reads, more storage and write maintenance.
  2. B-tree indexes: B-tree is the default general-purpose index in many relational databases.
  3. Hash indexes: Know that hash is not a general replacement for ordered or range access.
  4. Clustered vs non-clustered: Avoid presenting one vendor's implementation as universal SQL truth.
  5. Composite indexes: Choose column order from actual WHERE, JOIN and ORDER BY patterns.
