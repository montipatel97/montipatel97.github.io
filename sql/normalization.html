🧩 Normalization

Organize relational data to reduce redundancy and avoid insert, update and delete anomalies.

Start Learning ↓

Why normalize?

Normalization stores each fact in an appropriate place and reduces inconsistent duplicate data.

Interview focus

Name the three classic anomalies and explain how normalization prevents them.

Functional dependencies

A functional dependency X → Y means X determines Y.

Interview focus

Normalization decisions are based on candidate keys and dependencies.

1NF

Values should be atomic and repeating groups should be removed.

Interview focus

Why comma-separated values in one column are usually a design smell.

2NF

Be in 1NF and remove partial dependency on part of a composite key.

Interview focus

This matters when a table has a composite candidate key.

3NF

Be in 2NF and remove problematic transitive dependencies.

Interview focus

Explain transitive dependency with a department example.

BCNF

Every determinant should be a candidate key; BCNF is stricter than 3NF.

Interview focus

Know the trade-off between stronger normalization and dependency preservation.

Denormalization

Intentionally duplicate or precompute data for read performance when justified.

Interview focus

Integrity and write simplicity versus read speed is the core trade-off.

Quick interview recap

  1. Why normalize?: Name the three classic anomalies and explain how normalization prevents them.
  2. Functional dependencies: Normalization decisions are based on candidate keys and dependencies.
  3. 1NF: Why comma-separated values in one column are usually a design smell.
  4. 2NF: This matters when a table has a composite candidate key.
  5. 3NF: Explain transitive dependency with a department example.
