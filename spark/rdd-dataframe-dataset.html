SPARK CORE

Three ways to think about distributed data

Spark gives you different abstractions for distributed data. The three interview terms you must distinguish are RDD, DataFrame, and Dataset.

RDDLow-level distributed objects
DataFrameNamed columns + optimized engine
DatasetTyped JVM objects + optimized engine

The practical PySpark takeaway is simple: you will mostly use DataFrames. RDDs still matter for understanding Spark internals and occasionally for lower-level use cases. Dataset is primarily a Scala/Java API.

Interview focus

Start with the practical answer before going deep: PySpark work is predominantly DataFrame-based.

RDD

What exactly is an RDD?

RDD stands for Resilient Distributed Dataset. It is Spark's foundational abstraction: an immutable collection split into partitions that can be processed in parallel.

  • Resilient: lost partitions can generally be recomputed from lineage.
  • Distributed: partitions can live and execute across multiple machines.
  • Dataset: a collection of records/objects.
  • Immutable: transformations create a new RDD rather than modifying the existing one.

RDDs expose lower-level functional operations such as map, filter, flatMap, reduceByKey and mapPartitions.

Interview focus

RDD is not simply “old Spark.” It is the foundational distributed abstraction and is useful for understanding partitions, lineage, dependencies and execution.

RDD

Creating RDDs

You can create an RDD by parallelizing local data or by reading supported external data sources through Spark's lower-level APIs.

When parallelizing local data, Spark divides the collection into partitions so work can be processed in parallel.

Interview focus

Know parallelize for interview examples, but in production data engineering you more commonly read structured data into DataFrames.

numbers = [1, 2, 3, 4, 5]
rdd = spark.sparkContext.parallelize(numbers)

rdd2 = spark.sparkContext.textFile("s3a://bucket/input.txt")
RDD

RDD lineage and immutability

Each RDD transformation creates a new logical RDD connected to its parent through dependencies. Spark can use this lineage to understand how a partition was produced and recompute it if necessary.

Nothing is modified in place. The variable name may be reassigned in Python, but each transformation conceptually produces a new distributed dataset.

Interview focus

Immutability does not mean your Python variable cannot be reassigned. It means Spark transformations do not mutate the existing dataset in place.

DATAFRAME

What is a DataFrame?

A DataFrame is a distributed collection organized into named columns. It is conceptually similar to a database table, but Spark also understands the schema and the operations you express.

That additional structural information allows Spark SQL to analyze and optimize your computation using its query engine.

  • Named columns and schema.
  • High-level relational operations.
  • Optimizer can reason about many operations.
  • Common across Python, Scala, Java and R APIs.

Interview focus

The biggest interview difference from an RDD: a DataFrame exposes structure, giving Spark more information for optimization.

DATAFRAME

A simple DataFrame flow

DataFrame operations look similar to SQL and are the preferred API for most structured ETL workloads.

Interview focus

Explain that the operations below are transformations until an action or output operation requires execution.

df = spark.read.parquet("/data/orders")

result = (
    df.filter("amount > 100")
      .groupBy("country")
      .count()
)

result.show()
DATASET

What is a Dataset?

A Dataset is a distributed collection of typed domain objects that can use both functional transformations and Spark SQL's optimized execution engine. In Scala/Java, a DataFrame is represented as a Dataset of rows.

Important for PySpark: the strongly typed Dataset API is not available in Python in the same way it is in Scala/Java. In PySpark, the practical structured API is the DataFrame API.

Interview focus

Do not say Dataset is the Python equivalent of DataFrame. For interview purposes: Dataset API is primarily Scala/Java; PySpark primarily uses DataFrames.

DECISION MAKING

When should you use each?

Use DataFrames by default for structured data engineering: reading files, joins, aggregations, SQL-style transformations and most ETL pipelines.

Consider RDDs when you genuinely need lower-level control or are working with operations/data that do not fit the structured APIs well.

Use Datasets when working in Scala/Java and the benefits of strong typing and domain objects fit the application.

Interview focus

The strongest interview answer is usually: DataFrame by default, then explain the specific reason to move lower-level.

DATAFRAME

Why schema matters

A schema tells Spark about columns and data types. This helps Spark reason about structured operations rather than treating every record as an opaque application object.

Schema design also matters operationally: explicit schemas can reduce inference overhead and make pipelines more predictable.

Interview focus

Connect schema to optimization and reliability, but avoid claiming every schema-aware operation is automatically optimal.

MENTAL MODEL

The interview mental model

RDD = distributed objects.

DataFrame = distributed structured rows with named columns, enabling high-level query optimization.

Dataset = typed distributed domain objects with optimized execution in Scala/Java.

Interview focus

If asked “which one is faster?”, first ask about workload and API. Then explain why structured APIs often allow better optimization.

🔥 RDD vs DataFrame vs Dataset — Interview Q&A

1. What is an RDD?

An immutable, partitioned distributed collection that Spark can process in parallel and recover through lineage.

2. Why are DataFrames generally preferred?

They expose schema and structured operations, giving Spark more information to analyze and optimize many workloads.

3. What is Dataset?

A typed distributed collection with optimized execution, primarily used through Scala/Java APIs.

4. Does PySpark support typed Dataset API like Scala?

No. In PySpark, DataFrame is the primary structured API.

5. Is an RDD mutable?

No. Transformations create new RDDs and preserve lineage from the original.

6. When would you choose RDD?

When lower-level control is genuinely needed or the problem does not fit structured APIs well; otherwise DataFrames are usually the default for ETL.

7. Are DataFrames always faster?

Not as an absolute rule. The key advantage is that structured information often enables better planning and optimization.

8. What does schema add?

It describes named fields and types, enabling structured relational operations and giving Spark information it can use in planning.
