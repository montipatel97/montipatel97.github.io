INTERNALS

Spark SQL Pipeline

SQL/DataFrame→Parsed Logical Plan→Analyzed Plan→Optimized Plan→Physical Plan→Execution

Spark SQL translates declarative operations into plans, applies rules/optimization and finally chooses executable operators.

Interview focus

Know the pipeline end-to-end; this is the foundation for explaining Catalyst.

CATALYST

Catalyst Optimizer

Catalyst represents queries as trees of relational operators and expressions. Rules analyze unresolved references, optimize logical plans and help generate candidate physical plans.

Interview focus

Catalyst is not a single magic optimization; think parser → analysis → logical optimization → planning.

PLANS

Logical vs Physical Plan

LogicalWhat computation should happen.
PhysicalHow Spark plans to execute it.

Multiple physical strategies can sometimes implement the same logical operation.

Interview focus

When debugging performance, physical operators and exchanges matter most.

OPTIMIZER

Optimization Rules

Common concepts include predicate pushdown, column pruning, constant folding and join optimization. The optimizer tries to reduce work before execution.

Interview focus

A simple optimization often matters more than a low-level tuning parameter: read fewer rows and columns first.

EXECUTION

Physical Planning

Physical planning selects executable operators such as scan, filter, projection, aggregate, sort and join strategies. Exchanges mark repartitioning/shuffle boundaries.

Interview focus

Explain a slow query by connecting an Exchange or join operator in the physical plan to the corresponding Spark stage.

ENGINE

Tungsten & Code Generation

Tungsten is associated with Spark execution optimizations focused on efficient CPU and memory use. Whole-stage code generation can combine compatible operators into generated code paths to reduce overhead.

Interview focus

Do not say Tungsten means 'everything is in memory'. It is primarily about efficient execution and memory representation.

PRACTICE

Reading explain()

Parsed↓Analyzed↓Optimized↓Physical

Use explain to inspect scans, filters, exchanges and join strategies before guessing at performance fixes.

Interview focus

A production answer should pair explain() with Spark UI metrics.
