CONFIGURATION

Tuning Workflow

Baseline→Measure→Find Bottleneck→Change One Variable→Validate

Configuration is workload-specific. Start from data size and bottleneck evidence, not a copied list of magic numbers.

Interview focus

Never tune every property at once.

RESOURCES

Executors & Cores

Executor count controls parallel worker processes; cores affect concurrent task capacity per executor. Balance parallelism, memory pressure and scheduling overhead.

Interview focus

More cores per executor is not automatically better if memory or GC becomes the bottleneck.

MEMORY

Memory Configuration

Driver and executor memory must match workload needs. Diagnose execution memory, storage memory, overhead and partition size before simply increasing heap size.

Interview focus

Memory tuning without fixing skew often just postpones the same failure.

PARALLELISM

Partitions

Partition count influences task parallelism and partition size. Too few partitions can underutilize resources; too many can add scheduler overhead.

Interview focus

Target sensible partition sizes and measure actual task duration rather than memorizing a universal partition number.

AQE

Adaptive Query Execution

AQE can use runtime statistics to adapt supported query decisions, including coalescing shuffle partitions and handling supported skewed joins.

Interview focus

AQE helps, but it is not a replacement for understanding data shape and query design.

SHUFFLE

Shuffle Settings

Focus first on reducing unnecessary shuffle. Only then evaluate partition configuration, file layout and resource settings.

Interview focus

The best shuffle optimization is often eliminating the shuffle entirely.

STORAGE

File Layout

Output partitioning and file sizes affect downstream scans, scheduling and metadata overhead. Avoid both giant files and excessive tiny files.

Interview focus

Data layout is part of performance engineering, not an afterthought.

Q&A

Tuning Interview Vault

First tuning step?
Measure and identify the bottleneck.
More executors?
Useful only if parallelizable capacity is the bottleneck.
More partitions?
Balances parallelism vs overhead; does not cure hot keys.
AQE?
Runtime adaptation using observed statistics for supported decisions.

Interview focus

The strongest tuning answer is always evidence-driven.
