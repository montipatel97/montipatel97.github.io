SECTION 01

Architecture & Core

10 Q&A
1What are the main components of Spark?+
Answer

Driver coordinates the application, executors run tasks, and a cluster manager allocates resources.

2What is the DAG in Spark?+
Answer

A graph of transformations representing computation dependencies before execution.

3What is lazy evaluation?+
Answer

Transformations build a plan; execution starts when an action requires a result.

4What is a job?+
Answer

A unit of execution triggered by an action.

5What is a stage?+
Answer

A set of tasks that can run without requiring another shuffle boundary.

6What is a task?+
Answer

The smallest unit of work, generally processing one partition.

7What creates a new stage?+
Answer

A shuffle dependency typically creates a stage boundary.

8What is lineage?+
Answer

The dependency history Spark can use to recompute lost data.

9What is fault tolerance in RDDs?+
Answer

RDD lineage allows lost partitions to be recomputed.

10Driver vs executor?+
Answer

Driver plans and schedules; executors perform distributed computation.

SECTION 02

RDD, DataFrame & Dataset

10 Q&A
1RDD vs DataFrame?+
Answer

RDD is a lower-level distributed collection; DataFrame is schema-based and benefits from Spark SQL optimization.

2Why is DataFrame often faster?+
Answer

Schema awareness and the optimized SQL execution engine enable better planning and efficient execution.

3What is Dataset?+
Answer

A typed API available primarily in Scala and Java; PySpark uses DataFrames rather than typed Datasets.

4When would you use RDD?+
Answer

For low-level control or data shapes not suited to structured APIs, though DataFrames are preferred for most modern workloads.

5What is immutability?+
Answer

Transformations create new datasets rather than modifying an existing one.

6What is schema enforcement useful for?+
Answer

It makes columns and types explicit, enabling validation and optimization.

7Can DataFrames be partitioned?+
Answer

Yes. They are distributed across partitions just like other Spark datasets.

8What is SparkSession?+
Answer

The primary entry point for Spark SQL and DataFrame functionality.

9What is collect() and why is it risky?+
Answer

It brings all results to the driver and can cause driver memory failures.

10What is toPandas() risk?+
Answer

It materializes distributed data in the driver process, so large results can exhaust driver memory.

SECTION 03

Transformations & Actions

10 Q&A
1Transformation vs action?+
Answer

Transformations build a new logical dataset; actions trigger execution or return/write results.

2Narrow vs wide transformation?+
Answer

Narrow dependencies stay within partitions; wide dependencies require data redistribution and usually a shuffle.

3Why is reduceByKey preferred over groupByKey for aggregation?+
Answer

It can combine values locally before shuffle, reducing network transfer.

4What is map vs flatMap?+
Answer

map produces one output per input; flatMap can produce zero, one or many outputs and flattens them.

5What is filter?+
Answer

A transformation that retains rows/elements satisfying a condition.

6What is foreach?+
Answer

An action-like operation that executes a function for records; avoid relying on executor-side side effects unless designed carefully.

7Does count trigger execution?+
Answer

Yes, count is an action.

8Does cache trigger execution?+
Answer

No; caching is lazy and materializes when an action computes the dataset.

9What is checkpointing vs caching?+
Answer

Caching stores reusable computed data; checkpointing persists lineage/state for recovery semantics depending on API/use case.

10Why avoid repeated actions?+
Answer

Repeated actions can recompute lineage unless reusable results are persisted.

SECTION 04

Partitioning & Shuffle

10 Q&A
1What is a partition?+
Answer

A chunk of distributed data processed by one task at a time.

2What is shuffle?+
Answer

Redistribution of data across partitions, typically involving network, disk and scheduling overhead.

3What causes shuffle?+
Answer

Wide operations such as many joins, groupBy, distinct, orderBy and repartition.

4repartition vs coalesce?+
Answer

repartition reshuffles to redistribute; coalesce typically reduces partitions with less movement when possible.

5How do you choose partition count?+
Answer

Use data size, cluster parallelism and measured task sizes; avoid a universal magic number.

6Why can too many partitions hurt?+
Answer

Very small tasks increase scheduling and coordination overhead.

7Why can too few partitions hurt?+
Answer

Large partitions reduce parallelism and can create slow tasks or memory pressure.

8What is partition pruning?+
Answer

Skipping irrelevant partitions based on filters on partition columns.

9What is bucketing?+
Answer

Organizing data into a fixed number of buckets by a key to support compatible operations in some workloads.

10What is a shuffle spill?+
Answer

Intermediate data is written out when in-memory execution pressure requires spilling.

SECTION 05

Joins

10 Q&A
1What is broadcast join?+
Answer

A small side is sent to executors so the large side can avoid a full shuffle join.

2When should you not broadcast?+
Answer

When the relation is too large for practical executor memory or broadcasting creates unacceptable pressure.

3What is sort-merge join?+
Answer

A join strategy commonly used for large compatible inputs that involves partitioning/sorting by join keys.

4What is shuffle hash join?+
Answer

A strategy where shuffled partitions are used to build hash tables; suitability depends on size and planning decisions.

5How do you optimize joins?+
Answer

Filter/project early, inspect explain(), choose appropriate strategy and address skewed keys.

6What is join skew?+
Answer

A few keys have disproportionately many records, creating oversized partitions and straggler tasks.

7How does salting help?+
Answer

It spreads a measured hot key across multiple partitions by adding controlled key variation.

8What is AQE skew handling?+
Answer

Runtime adaptive logic can optimize supported skewed shuffle partitions based on observed statistics.

9What should you inspect before tuning a join?+
Answer

The physical plan, input sizes, key distribution and Spark UI shuffle/task metrics.

10Why can a small dimension still be problematic?+
Answer

It may not be small enough to broadcast safely after serialization or may be duplicated across executor memory.

SECTION 06

Memory, Cache & Persist

10 Q&A
1Cache vs persist?+
Answer

cache is a convenient default persistence choice; persist lets you choose a storage level.

2When should you cache?+
Answer

When an expensive intermediate is reused multiple times and the measured reuse benefit exceeds storage cost.

3When should you avoid caching?+
Answer

For one-time datasets, cheap recomputation, or datasets that cause eviction and memory pressure.

4What is unpersist()?+
Answer

It releases persisted data when it is no longer needed.

5Execution vs storage memory?+
Answer

Execution supports operations such as joins/sorts/aggregations; storage retains cached data.

6What is spill?+
Answer

Writing intermediate data outside memory when execution cannot retain everything in memory.

7Why can caching slow a job?+
Answer

Materialization, serialization, eviction and memory pressure can cost more than recomputation.

8What causes executor OOM?+
Answer

Skew, oversized partitions, large joins, excessive caching or insufficient working memory are common causes.

9What causes driver OOM?+
Answer

collect(), toPandas(), large driver-side metadata/results or oversized driver operations.

10How do you debug memory?+
Answer

Inspect failed task patterns, executor metrics, Storage usage and workload partition sizes before changing heap settings.

SECTION 07

Spark SQL & Internals

10 Q&A
1What is Catalyst?+
Answer

Spark SQL's framework for representing, analyzing and optimizing query plans.

2Logical vs physical plan?+
Answer

Logical describes what to compute; physical describes executable strategies for how to compute it.

3What does explain() show?+
Answer

Query plans that help reveal scans, filters, exchanges and join strategies.

4What is predicate pushdown?+
Answer

Pushing eligible filters toward the data source to reduce data read.

5What is column pruning?+
Answer

Reading only columns required by the query.

6What is constant folding?+
Answer

Evaluating constant expressions during optimization rather than at runtime.

7What is an Exchange?+
Answer

A physical-plan boundary indicating data redistribution, often associated with shuffle.

8What is whole-stage code generation?+
Answer

Combining compatible operators into generated execution code to reduce overhead.

9What is Tungsten associated with?+
Answer

Efficient Spark execution, including memory and CPU-oriented optimizations.

10How do SQL plans relate to Spark UI?+
Answer

Physical operators such as exchanges and joins often map to expensive stages and task metrics.

SECTION 08

Optimization & AQE

10 Q&A
1What is AQE?+
Answer

Adaptive Query Execution uses runtime statistics to adjust supported physical decisions during execution.

2What can AQE help with?+
Answer

Supported capabilities include coalescing shuffle partitions and optimizing certain skewed joins.

3Is AQE a replacement for tuning?+
Answer

No. Data shape, query design and resource bottlenecks still matter.

4Best first optimization?+
Answer

Reduce unnecessary work: filter early, select fewer columns and avoid unnecessary shuffles.

5How do you optimize a slow job?+
Answer

Find the bottleneck in Spark UI, inspect task distribution and plan, then apply a targeted fix and measure again.

6Why is input file layout important?+
Answer

File counts and sizes affect scan, metadata and scheduling overhead.

7How do small files hurt?+
Answer

Many tiny tasks/files increase scheduling and metadata overhead.

8How do you validate optimization?+
Answer

Compare relevant before/after metrics such as stage duration, shuffle, task skew and resource pressure.

9Why change one variable at a time?+
Answer

It lets you attribute performance changes to a specific modification.

10What is premature optimization risk?+
Answer

Tuning non-bottlenecks adds complexity without meaningful performance improvement.

SECTION 09

Structured Streaming

10 Q&A
1What is Structured Streaming?+
Answer

A scalable stream-processing engine built on Spark SQL where streaming computations are expressed with structured APIs.

2Default execution model?+
Answer

Micro-batches process newly available data as a sequence of small batch jobs.

3What is event time?+
Answer

The time the event actually occurred.

4What is processing time?+
Answer

The time Spark processes the event.

5What is a watermark?+
Answer

A threshold used in supported operations to manage late data and bound state retention.

6Append vs Update vs Complete?+
Answer

They control whether newly final rows, changed rows, or the full result are emitted, subject to query support.

7Why checkpoint?+
Answer

To store progress/state information needed for fault-tolerant recovery.

8What is stateful processing?+
Answer

Operations retain information across batches, such as windows, aggregations, deduplication or streaming joins.

9Why are stream-stream joins difficult?+
Answer

Both sides are unbounded, so state must have conditions for bounded retention and cleanup.

10How do you debug streaming lag?+
Answer

Compare sustained input and processing rates, batch duration, state size and sink bottlenecks.

SECTION 10

Production Scenarios

10 Q&A
1One task is much slower than others. What do you do?+
Answer

Compare task input/shuffle sizes and key distribution; suspect skew or an oversized partition before adding cluster resources.

2A job suddenly becomes slow. First step?+
Answer

Identify the slow stage in Spark UI and compare input volume, shuffle, task distribution and plan changes.

3High GC but low progress. What next?+
Answer

Investigate memory pressure, object churn, partition size and caching before low-level GC tuning.

4Repeated task retries. What do you inspect?+
Answer

The first meaningful exception and whether the same data partition deterministically fails.

5Streaming backlog grows continuously. Why?+
Answer

Sustained input rate exceeds effective end-to-end processing capacity.

6Kafka lag is high. Is adding executors always the fix?+
Answer

No. Find whether the bottleneck is Spark parallelism, skew, transformation cost, sink throughput or partitioning.

7Checkpoint issue after deployment. What is the principle?+
Answer

Treat checkpoint data as part of query recovery identity and avoid casual deletion or incompatible reuse.

8How do you debug a slow join?+
Answer

Inspect explain(), shuffle metrics, input sizes, join strategy and key skew.

9How do you answer a production scenario?+
Answer

Use symptom → evidence → diagnosis → targeted fix → validation.

10What is the biggest Spark troubleshooting mistake?+
Answer

Changing many configurations without evidence and losing the ability to identify the real bottleneck.
